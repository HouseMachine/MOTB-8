## 1. Release Overview

MOTB-8, Machine Open Tag & Beacon, is an open-source, ecosystem-neutral standard for persistent, discoverable machine presence.

Make Your Machine Discoverable.

This first versioned release provides a working reference implementation, command-line interface, cryptographic identity lifecycle, and portable publishing tools.

The release is designated a pre-release and is not represented as production-certified or enterprise-certified.

## 2. Included Capabilities

- Permanent MOTB-8 Tag generation, parsing, and checksum validation.
- Signed Genesis Records and cryptographic controller binding.
- Signed Beacons and authorized revisions.
- Encrypted Control Files and controller authorization.
- Beacon v1.0 to v1.1 migration and signed revision history.
- Machine-presence metadata, capabilities, catalogs, protocols, and discovery profiles.
- Industry taxonomy and reference capability vocabulary.
- Public artifact packaging and SHA-256 integrity manifests.
- Local write-lock safeguards and recovery diagnostics.

## 3. Command-Line Interface

The release provides five CLI commands:

- create: Generate a machine presence and its initial artifacts.
- verify: Verify a signed Beacon against Genesis.
- migrate: Establish a v1.1 revision chain from an authorized legacy Beacon.
- update: Create an authorized signed Beacon revision.
- publish: Prepare a portable public artifact package.

The CLI does not require a hosted account, centralized registry, or Monet integration.

## 4. Verification Results

The final release validation completed 254 automated tests with zero failures.

The full Create, Migrate, Update, Verify, and Publish workflow was successfully tested on Windows.

A six-artifact public publication package was verified using SHA-256 hashes, with the encrypted Control File excluded.

The npm package dry run confirmed 296 files, including compiled code, CLI, specifications, schemas, vocabularies, documentation, README, and MIT license.

Windows testing used Node.js 24.14.0. Equivalent cross-platform behavior was not independently established for this release.

## 5. Security and Operational Limitations

- Multi-file operations are not fully crash-atomic.
- Interrupted operations may require manual recovery.
- Write locking coordinates cooperating processes.
- Filesystem race and durability guarantees are limited by the implementation and operating environment.
- Cryptographic verification does not independently establish publication freshness, original ownership anchoring, the truth of operator claims, lawful behavior, or machine trustworthiness.

These limitations are documented and do not constitute a claim of enterprise production certification.
